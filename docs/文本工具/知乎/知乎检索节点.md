# 知乎检索节点（`zhihu_search`）

> 文本工具节点：聚合知乎开发者平台 3 类检索能力（站内搜索 / 全网搜索 / 直答），
> 结果统一整理为 **Markdown 文本** 写入 `data.output`，供下游节点（文本聚合 / 提示词生成 /
> 图像生成 / AI 对话…）按「端口类型声明」自动消费，无需逐个枚举节点类型。

## 一、集成概览

| 层 | 文件 | 改动 |
|---|---|---|
| 后端服务 | `backend-ts/src/services/zhihu-service.ts`（新增） | 3 类 API 调用 + 响应整理为 Markdown 文本 |
| 后端执行 | `backend-ts/src/modules/bookplate/router.ts` | 新增 `POST /api/modules/bookplate/zhihu-search` |
| 后端模板 | `backend-ts/src/modules/bookplate/node-types.ts` | `ZHIHU_SEARCH` 模板：`tool` / 输出 `text` / 接受 `text` |
| 凭据 | `backend-ts/src/config/env.ts` + `seed.ts` | `ZHIHU_ACCESS_SECRET`（.env）→ `zhihu.access_secret`（`/admin/settings`，敏感项） |
| 前端类型 | `frontend/src/platform/types/index.ts` | `CanvasNodeType` 增加 `'zhihu_search'` |
| 前端展示 | `frontend/src/modules/bookplate/nodeTypes.ts` + `nodeLayout.ts` | 尺寸 / 颜色 / 模板 / 端口静态镜像 |
| 前端组件 | `frontend/src/modules/bookplate/components/ZhihuSearchNode.tsx`（新增） | 节点交互 UI（模式切换 / 表单 / 结果展示） |
| 画板接线 | `BookplatePage.tsx` / `CanvasNodeViews.tsx` / `useNodeExecution.ts` | `seedDataFor` / `handleFetchZhihuFor` / 渲染分支 / `runNode` 分支 |
| 管理端 | `frontend/src/admin/pages/SettingsPage.tsx` | `zhihu.access_secret` 配置项 + 「知乎检索」分类 |

**端口声明（唯一权威：后端模板）**

```python
{
    "type": "zhihu_search",
    "name": "知乎检索",
    "category": "tool",            # 「+」菜单 → 文本工具 分组
    "configurable": false,         # 不绑定 llm/agent 配置
    "output_type": "text",         # 结果以文本输出（占位符引用 / 文本上下文自动生效）
    "input_types": ["text"],       # 可连线上级文本节点传入关键词 / 问题
}
```

> 按「节点输入输出声明式接线」约定：声明 `output_type: "text"` 且把对外文本存入
> `data.output` 后，文本聚合占位符引用、提示词生成 / 图像生成 / AI 对话的「文本上下文」
> 收集均**零改动自动生效**；连线上级文本作为检索关键词与天气节点同口径（连线即输入，1 级）。

## 二、凭据配置

- 管理端「系统设置」→「知乎检索」分类：`zhihu.access_secret`（敏感项，仅显示掩码）；
- 初始种子自 `.env` 的 `ZHIHU_ACCESS_SECRET`（种子回填 `zhihu.*`：存量值为空且种子非空时补写，
  绝不覆盖管理端修改）；
- 未配置时节点查询返回 503，错误文案引导到 `/admin/settings` 或 `.env`。

鉴权（3 类接口统一）：

```
Authorization: Bearer <access_secret>
X-Request-Timestamp: <秒级 Unix 时间戳>
Content-Type: application/json
```

## 三、3 类检索与后端契约

`POST /api/modules/bookplate/zhihu-search`，请求体：

```jsonc
{
  "mode": "zhihu",          // zhihu（站内搜索）/ global（全网搜索）/ zhida（直答）
  "query": "RAG 评测方法",  // 检索关键词 / 直答问题（必填；页面以上级连线文本优先覆盖）
  "count": 5,               // 请求数量：zhihu 1-10 / global 1-20（后端自动收敛）
  "filter": "",             // global 专属：高级筛选语法，如 host=="example.com" AND publish_time>=1778494631
  "search_db": "all",       // global 专属：all / realtime / static
  "model": "zhida-fast-1p5" // zhida 专属：zhida-fast-1p5 / zhida-thinking-1p5 / zhida-agent
}
```

响应统一为 `{ output, ... }`，`output` 即对外 Markdown 文本：

| 模式 | 上游 API | 输出形态 |
|---|---|---|
| 站内搜索 | `GET /api/v1/content/zhihu_search` | `# 知乎搜索 · 关键词` + 逐条 `### [标题](URL)`、摘要、`> 作者 · 赞同 N · 评论 N · 类型 · 时间` |
| 全网搜索 | `GET /api/v1/content/global_search` | 同上（`# 全网搜索 · 关键词`）；摘要中的 `<em>` 高亮标签已剥离 |
| 直答 | `POST /v1/chat/completions`（`stream: false`） | 回答正文（模型 `content`）原样输出 |

错误码（`Code != 0` / HTTP 非 2xx / `error.message`）统一映射为 502 + `detail`；
前端以 `error.detail` 展示并可重试。超时前端 30s（`SMALL_TOOL_TIMEOUT_MS`）、后端 15s。

## 四、节点交互设计

```
┌─ 知乎检索 ● ──────────────────────────────┐
│ [知乎搜索] [全网搜索] [直答]   ← 模式页签  │
│                                           │
│ ┌ 关键词输入 ─────────┐ [数量▾] [🔍]      │
│ └─────────────────────┘                   │
│ 高级筛选（仅全网搜索，可展开）             │
│   ├ 索引库：全部 / 实时 / 静态             │
│   └ Filter 语法输入（只读提示示例）        │
│                                           │
│ （直答模式：模型档位下拉 + 问题输入 + 提问）│
│                                           │
│ ┌ 结果（Streamdown Markdown）───────────┐ │
│ │ # 知乎搜索 · RAG 评测方法              │ │
│ │ ### [RAG 评测方法综述](…)              │ │
│ │ 本文介绍了主流 RAG 评测框架…            │ │
│ │ > 张三 · 赞同 128 · 评论 15 · 文章 · … │ │
│ └──────────────────────────────────────┘ │
└───────────────────────────────────────────┘
```

- **模式页签**：3 类检索一键切换；切换时数量档位自动收敛到该模式上限
  （全网 20 → 站内 10），避免越界请求；
- **连线即输入**：连接文本输出上级后，表单收敛为「上级连线输入关键词/问题」高光卡片
  （与天气节点一致），查询以上级文本为准；断开连线即回到手动输入；
- **数量档位**：站内 3/5/10 条，全网 5/10/20 条（对应服务端上限 10 / 20）；
- **高级筛选（全网搜索）**：默认折叠，展开后提供索引库下拉 + Filter 语法输入，
  适合需要限定站点 / 发布时间的高级检索；
- **直答**：模型档位下拉（快速回答 / 深度思考 / 智能思考，附 tooltip 说明）+ 问题输入 +
  「提问」按钮；回答正文直接作为文本输出；
- **结果区**：加载态（BeamGlow + 旋转指示 + 当前关键词）、错误态（原因 + 重试）、
  结果态（Streamdown Markdown 渲染，可复制 / 重新检索）；右上角操作栏提供
  「重试 / 复制」；有下级节点时禁用影响输出的操作；
- **对外输出**：结果存入 `data.output`，不写入历史记录（与万年历 / 天气查询同口径，
  纯文本工具节点）。
