# 图片处理节点 · 效果接入指南

> 「图片处理」节点（`image_process`，多模态工具类别）支持在**同一个节点内切换多种图片处理效果**
> （已实现：噪点 / 网点 / 抖动 / ASCII）。本文是该节点的架构总结，
> 以及**后续新增处理模式时的最佳实践**——目标：新效果只写一个文件 + 注册一行，其余全部自动生效。

- 节点接线契约：`docs/节点输入输出声明式接线.md` §2 `image_process` 行
- 算法参考目录：`docs/多模态工具/图片处理/`（噪点 = Grainy-image-main，MIT）
- 多模板模式来源：「图书小票」（`receipt_printer`）的 templates.ts 注册表 + buildReceiptState 核心函数

---

## 1. 节点概览

### 1.1 数据流（端到端）

```
连线输入（resolveUpstreamImage：直连图片 > 连通图书封面 > 根节点封面兜底）
        ↓
activeImageSrc = data.uploadedImage || upstreamImageUrl     ← 本地上传优先
        ↓
applyImageFx(effectId, src, params, { maxEdge })
  ├─ 编辑态实时预览：maxEdge=1024，参数变化防抖 150ms 重渲
  └─ 点击「生成」：maxEdge=2048 全尺寸 → data.imageUrl（isSaved=false）
        ↓
data.imageUrl（对外输出唯一约定字段）
  ├─ 下游节点：nodeOutputImages 按 data.imageUrl 约定自动读取（零改动）
  └─ 「保存到数据库」：useImageExportHandler → POST /save-image 落盘
      → generations 记录（prompt = `图片处理 · ${effectName}`）→ 解锁收藏/公开
```

### 1.2 文件职责（`frontend/src/modules/multimodal/imageprocess/`）

| 文件 | 职责 | 新增效果是否要改 |
|---|---|---|
| `types.ts` | `ImageFxId`、`ImageFxEffectDef`（效果定义接口）、参数声明类型、`ImageProcessState` | ✅ 加 id 到联合类型 |
| `shared.ts` | `fxLoadImage` / `fxDrawingCanvas` / `fxDefaultParams`（渲染公共工具） | ❌ 直接复用 |
| `effects/<id>.ts` | 单个效果：参数 schema + render 实现 | ✅ **新建一个文件** |
| `effects/registry.ts` | 效果注册表 Map + getAll/get（未知 id 兜底首个）/ register | ✅ 登记一行 |
| `state.ts` | `resolveFxParams`（参数读取兜底）+ `switchFxEffectPatch`（切换补丁） | ❌ 不改 |
| `index.ts` | re-export + `applyImageFx` 统一渲染分发 | ❌ 不改 |
| `components/ImageProcessNode.tsx` | 节点组件（编辑态/结果态双态、按钮组、预览） | ❌ 不改 |

### 1.3 三条核心语义（设计不变量，勿破坏）

1. **输出与所选效果强一致**：切换效果 = 旧结果立即失效。
   `switchFxEffectPatch()` 清空 `imageUrl` / `isSaved` 回编辑态——保证下游读到的
   `data.imageUrl` 与保存到 db 的记录**始终对应当前所选效果**。任何新增交互都不得绕过它。
2. **参数按效果分桶**：`data.fxParams[effectId]` 各存各的，切换互不覆盖、切回自动恢复；
   读取一律走 `resolveFxParams()`（缺字段安全回落默认值），不要自己读原始 bucket。
3. **预览即结果**：预览与「生成」共用同一 render 实现，仅 `maxEdge` 不同。
   效果的 render 必须是纯函数式的「输入图 + 参数 → 结果画布」，禁止依赖会话式内部状态。

## 3. 参数声明规范

UI 由组件按 `params` 声明**自动渲染**（滑杆每行两个、分段独占一行右对齐），
顺序即声明顺序：

| kind | 字段 | 渲染形态 |
|---|---|---|
| `'slider'` | key / label / min / max / step / default / display? | 滑杆行（display 格式化右侧数值，如 `${Math.round(v*100)}%`） |
| `'segment'` | key / label / default / options[{value,label}] | 分段按钮组（如 单色\|彩色） |

规则：

- **default 是单一事实来源**：默认参数表由 `fxDefaultParams(params)` 从声明提取，
  UI 初值、历史数据兜底、db 记录共用，禁止另设默认值常量；
- 参数值只允许 `number | string`（滑杆数值 / 分段字符串）；布尔开关用两档 segment 表达；
- 参数存储在 `data.fxParams[effectId][key]`，**不同效果的 key 天然隔离**，
  无需跨效果去重命名（但同一效果内 key 必须唯一且语义稳定——它是持久化契约）；
- 改已有效果的 default 只影响未调过参的新节点；老节点已持久化的参数不受影响（预期行为）。

## 4. render 实现规范（性能与正确性）

1. **复用 shared 工具**：加载用 `fxLoadImage`（crossOrigin anonymous + 可读报错），
   画布与缩放用 `fxDrawingCanvas(img, maxEdge)`（自带最长边限制 + `willReadFrequently`）。
   不要自建 Image / canvas 流程。
2. **尊重 `options.maxEdge`**：预览传 1024、导出传 2048，render 内部按最长边缩放——
   这是「预览快、导出清晰」的基础，忽略它会导致预览卡顿。
3. **像素操作**：
   - `getImageData` → 改 `Uint8ClampedArray` → `putImageData`；
     数组写入越界 [0,255] 自动钳制，无需手动 clamp（噪点即此做法）；
   - 保留原图 alpha 通道（除非效果本身要求不透明底）；
   - 大图全图循环注意复杂度：单次 O(w×h) 线性扫描可接受（2048² ≈ 4M 像素 <100ms）；
     避免每像素再开 O(n) 子循环（如逐像素排序/搜索），必要时先降采样。
4. **随机性**：允许使用 `Math.random()`（噪点口径：每次生成有细微变体，「重新调整→生成」天然多样）；
   若效果要求可复现（如确定性抖动矩阵），把 seed 作为参数并使用带种子的伪随机。
5. **错误处理**：跨域封面可能导致 Canvas taint（`SecurityError`）、图片 404 等——
   一律 `throw new Error('中文可读信息')`，组件会把预览失败显示为错误态 + 重试按钮、
   把生成失败显示为 toast。**不要吞错或返回空画布假装成功**。
6. **返回 HTMLCanvasElement**（不是 dataURL）：toDataURL 统一由 `applyImageFx` 处理（PNG）。

## 5. 边界与禁止事项

- ❌ 不要在 `ImageProcessNode.tsx` 里写 `if (effect.id === 'xxx')` 的效果分支逻辑——
  效果差异全部收敛在各自的 effect 文件里，注册表是唯一分发点；
- ❌ 不要绕过 `switchFxEffectPatch` 自行处理切换（会破坏「输出=所选效果」不变量）；
- ❌ 不要把效果参数写到 `fxParams` 桶之外的顶层字段（小票式平铺在本节点已弃用，勿混入）；
- ❌ 不要在 render 里访问 React / DOM 节点 / 全局单例缓存——纯函数才能保证预览与导出一致；
- ⚠️ 若效果需要**非声明式 UI**（自由文本、取色器、字符集预设等），两条路径二选一：
  1. 通用性强 → 扩展 `ImageFxParamDef` 新增 kind（如 `'text'`），并在组件的参数渲染区补一个分支
     （改一处组件，所有效果受益）；
  2. 单个效果特有 → 参照小票 `ancient_bookmark` 规格选择器的条件渲染模式
     （ReceiptToolbar 中 `templateId === 'ancient_bookmark' && <专属选择器/>`），
     在控制栏追加该效果的专属区块；状态仍存 `fxParams[ascii].xxx`。

## 6. 待实现效果算法备忘

| 效果 | id 建议 | 算法要点 | 关键参数（建议） |
|---|---|---|---|
| ASCII | `ascii` | 亮度 → 字符梯度映射（如 `@#%*+=-:. `），可选按行列绘制等宽字符到画布；彩色版保留原色填充 | 字符集密度 / 分辨率（列数）/ 彩色开关 |
| 网点 | `halftone` | 图像栅格化为圆点阵：按局部亮度决定点半径（经典印刷网点）；可选旋转角度做 CMYK 风格 | 点距 / 最大半径比 / 角度 / 彩色通道分离开关 |
| 抖动 | `dither` | 二值化 + 误差扩散（Floyd–Steinberg / Bayer 有序抖动 / Atkinson），小票模块 `receipt/dither.ts` 已有 Floyd–Steinberg 实现可参考复用 | 算法选择(segment) / 阈值 / 色阶数 |

> 小票模块已有现成的抖动实现：`frontend/src/modules/multimodal/receipt/dither.ts`
> （封面点阵化）。若可直接复用，在 effect 文件里 import 它即可，避免复制粘贴。

## 7. 验证清单（每个新效果完成后）

1. `cd frontend && npm run build && npm run lint`；后端无改动则无需 typecheck；
2. 浏览器手动路径：
   - 图片上传 → 图片处理 → 下拉切到新效果 → 拖动每个参数看实时预览（150ms 防抖生效）；
   - 「生成」→ 结果与预观一致（除随机变体）→「直接下载」PNG 正确；
   - 「保存到数据库」→ 历史记录 prompt 为 `图片处理 · <效果名>`；
   - 连接下级节点 → 下游手动点「运行」时读取本节点最新输出（源头随时可改，无禁改门禁）；
   - 断开后级 → 切换效果 → 确认旧结果被清空回编辑态、切回原效果参数已恢复；
   - 异常路径：连线豆瓣封面（可能 taint）确认错误文案与重试可用。
