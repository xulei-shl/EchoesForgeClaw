# 图书卡片节点 · 补充字段接入指南

> 「图书卡片」节点（`book_card`）的 HTML 模板占位符中，**部分字段图书元数据节点（`book_info`，豆瓣 API 口径）
> 并不提供**（如索书号及其二维码）。本文档记录这些缺失字段的现状、兜底行为与后续接入路径，
> 供后期新增「索书号」等专门节点或扩展新占位符时参考。

配套代码：
- 字段解析 `frontend/src/modules/multimodal/bookcard/fields.ts`（占位符清单 / 映射 / JSON 补充字段解析）
- 资源改写 `frontend/src/modules/multimodal/bookcard/render.ts`（`resolveTemplateAsset()`，qrcode 等资源替换点）
- 模板源 `frontend/src/modules/multimodal/bookcard/html/*.html`（移植自 `docs/多模态工具/书目推广卡片/card_temples`）

## 2. 补充字段的注入机制（`parseExtraCardFields`）

设计原则：**不改执行引擎、不加新端口类型**——复用「连线即输入」既有机制，专门节点以
**文本输出 + JSON 约定** 向图书卡片节点传值。

```
[索书号节点] ──(text)──▶ [图书卡片 book_card]
                            │ upstream 文本 JSON.parse
                            ▼
        {"CALL_NUMBER": "I247.5/123"} → 覆盖 {{CALL_NUMBER}}
```

- **解析入口**：`fields.ts` 的 `parseExtraCardFields(raw)` —— 取上级文本节点内容，
  可解析为 JSON 对象时按键提取，非 JSON 文本静默返回空表（不影响主流程）；
- **键名约定**：与占位符同名（`CALL_NUMBER` 等 `CARD_PLACEHOLDERS` 清单内的键）；
- **优先级**：extra 同名键 **覆盖** 元数据默认值（`resolveCardFields(book, extra)` 的合并顺序）；
- **多上级**：当前实现按上游文本逐个尝试、命中即用；建议专门节点与图书卡片直连（1 级），
  与「连线即输入」口径一致。

> 组件侧接线位置：`BookCardNode.tsx` 目前仅消费 `upstreamBookData`；
> 接入专门节点时在此处增加「上游文本 → `parseExtraCardFields` → `resolveCardFields` 第二参」的传递即可
> （参考 `CanvasNodeViews.tsx` 中 `firstUpstreamText` 的用法）。

## 3. 二维码（`pic/qrcode.png`）——已实现，激活依赖索书号

> **依赖链（重要）**：二维码内容 = f(索书号 `CALL_NUMBER`) → 而 `CALL_NUMBER` 当前**恒为空**
> （图书元数据节点不提供）→ 因此在「索书号」专门节点接入前：
> 占位符文本留空、二维码位置为透明占位——这是预期行为，不是缺陷。
> 专门节点落地后按第 2 节机制注入 `{"CALL_NUMBER": "..."}`，文本与二维码同时自动生效。

移植自 `card_generator/qrcode_generator.py`，实现在 `frontend/src/modules/multimodal/bookcard/qrcode.ts`：

- **链接规则**：字段值（当前 = `{{CALL_NUMBER}}` 索书号）经 `encodeURIComponent` 后填入
  vufind 模板 `https://vufind.library.sh.cn/Search/Results?searchtype=vague&lookfor={call_number}&type=CallNumber`
  （`buildVufindSearchUrl()`），扫码即打开检索页；
- **出码参数**：纠错级别 H、白色背景转全透明（与原 PIL 像素处理等效）、输出 256px PNG data URL；
- **触发时机**：`BookCardNode` 填充 effect 中，`CALL_NUMBER` 非空才出码并替换 `pic/qrcode.png` 引用；
  出码失败或值为空回退透明像素占位，不阻断渲染；
- **激活路径**：出码逻辑已就绪、无需再动；唯一剩余步骤 = 第 2 节备注的**一次性组件接线**
  （`BookCardNode.tsx` 把上游文本经 `parseExtraCardFields()` 传入 `resolveCardFields()` 第二参），
  完成后索书号文本与二维码即随连线自动出现；
- 若后续需配置化 vufind 域名 / 链接模板：改 `qrcode.ts` 的 `VUFIND_URL_TEMPLATE`
  （或接管理端「系统设置」既有机制），勿散落硬编码。

## 4. 新增占位符 Checklist

为模板引入一个元数据节点没有的新字段（示例：`{{SHELF_LOCATION}}` 架标号）：

1. **模板**：在 `html/*.html` 中使用 `{{SHELF_LOCATION}}`；
2. **注册键名**：`fields.ts` 的 `CARD_PLACEHOLDERS` 数组加入 `'SHELF_LOCATION'`
   （同时决定它可被 `parseExtraCardFields` 覆盖）；
3. **缺省值**：`resolveCardFields()` 返回对象中补 `SHELF_LOCATION: ''`（缺省必须留空串，勿抛错）;
4. **专门节点**（后续落地时）：输出 `{"SHELF_LOCATION": "..."}` JSON 文本并连线到图书卡片节点；
5. **验证**：无专门节点时卡片该处留空且布局正常；连上专门节点后值正确填充、预览与导出一致。
