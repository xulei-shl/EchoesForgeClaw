这是一套针对**“纯局域网、多账号协同、Ubuntu 无 GPU 服务器”**量身定制的完整落地设计方案。

整个方案的核心思想是：**“算力边缘化（客户端浏览器计算），数据与模型集中化（Ubuntu 服务器负责存储与分发）”**。

---

### 一、 总体系统架构设计

```
┌─────────────────────────────────────────────────────────────┐
│ 局域网客户机 (浏览器端)                                     │
│  1. 访问系统 (通过局域网 HTTPS)                             │
│  2. 首次加载：从 Ubuntu 秒级下载 100MB 模型并缓存到本地     │
│  3. 本地推理：调用客户机显卡/核显(WebGPU)对用户上传的图片抠图 │
│  4. 结果回传：将抠图后的透明 PNG 提交至服务端 API            │
└──────────────┬───────────────────────────────▲──────────────┘
               │ 上传结果 (带账号 Token)       │ 下载页面/模型
               ▼                               │
┌─────────────────────────────────────────────────────────────┐
│ Ubuntu 服务器 (无 GPU，纯 CPU)                              │
│                                                             │
│  [Nginx]                                                    │
│    ├── 1. 提供局域网 HTTPS 证书（解锁浏览器 WebGPU）        │
│    ├── 2. 静态加速：托管前端静态资源 & ONNX 离线模型文件     │
│    └── 3. 反向代理：转发 API 请求到后端业务进程             │
│                                                             │
│  [后端服务 (Node.js / Python / Go)]                         │
│    ├── 用户认证 (JWT / Session 区分不同账号)                │
│    ├── 接收前端抠完的 PNG 图片                              │
│    └── 隔离落盘：/data/uploads/{user_id}/cutouts/          │
│                                                             │
│  [数据库 (PostgreSQL / MySQL / SQLite)]                     │
│    └── 记录图片归属、元数据、操作日志                       │
└─────────────────────────────────────────────────────────────┘
```

### 二、 Ubuntu 服务端配置（基础环境与模型准备）

#### 1. 生成局域网可信 SSL 证书（启用 WebGPU 必备）
WebGPU 强制要求安全上下文（HTTPS）。在局域网内，推荐使用 `mkcert` 工具：

```bash
# 1. 安装 mkcert (以 Ubuntu 为例)
sudo apt install libnss3-tools
curl -JLO "https://dl.filippo.io/mkcert/latest?for=linux/amd64"
chmod +x mkcert-v*-linux-amd64 && sudo mv mkcert-v*-linux-amd64 /usr/local/bin/mkcert

# 2. 生成根证书并生成服务器局域网证书（假设 Ubuntu IP 为 192.168.1.100）
mkcert -install
mkcert 192.168.1.100 localhost 127.0.0.1
# 生成了 192.168.1.100+2.pem 和 192.168.1.100+2-key.pem

# 3. 将 mkcert 的根证书 rootCA.pem 导出，导入到局域网各办公电脑的受信任根证书中（或让管理员统一下发），浏览器就不会提示不安全。
```

#### 2. 下载并离线化 BiRefNet ONNX 模型
在 Ubuntu 服务器上下载模型文件，供局域网内网直接访问：

```bash
# 创建静态资源模型目录
sudo mkdir -p /var/www/models/birefnet

# 安装 huggingface-cli 并拉取 Xenova 量化版的 birefnet-general
pip install huggingface_hub
huggingface-cli download Xenova/birefnet-general \
  --local-dir /var/www/models/birefnet \
  --local-dir-use-symlinks False
```
*下载完成后，该目录下应包含 `onnx/model_quantized.onnx`、`config.json`、`preprocessor_config.json` 等配置文件（体积约 100~130MB）。*

#### 3. 配置 Nginx（模型分发、HTTPS 与反向代理）
编辑 `/etc/nginx/sites-available/default`：

```nginx
server {
    listen 443 ssl http2;
    server_name 192.168.1.100;

    ssl_certificate /path/to/192.168.1.100+2.pem;
    ssl_certificate_key /path/to/192.168.1.100+2-key.pem;

    # 1. 托管前端单页应用
    location / {
        root /var/www/frontend/dist;
        try_files $uri $uri/ /index.html;
    }

    # 2. 托管离线模型文件（开启强缓存，局域网千兆传输）
    location /models/ {
        alias /var/www/models/;
        add_header Access-Control-Allow-Origin *;
        add_header Cache-Control "public, max-age=31536000, immutable";
        types {
            application/octet-stream onnx;
            application/json json;
        }
    }

    # 3. 后端业务 API（带身份鉴权的多账号接口）
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        client_max_body_size 50M; # 允许上传较大图片
    }
}
```

### 三、 前端工程实现（WebGPU 离线推理与回传）

前端引入 `@huggingface/transformers`（支持 Vite/Webpack 或原生 ESModule）：

```bash
npm install @huggingface/transformers
```

#### 前端完整处理模块 (`bgRemovalService.js`)

```javascript
import { pipeline, env } from '@huggingface/transformers';

// 1. 禁用公网连接，强制从局域网 Ubuntu 服务器加载
env.allowRemoteModels = false;
env.localModelPath = '/models/'; // 对应 Nginx 的 /models/ 路由

let segmenterInstance = null;

// 初始化模型（单例模式）
export async function initModel(onProgress) {
  if (segmenterInstance) return segmenterInstance;

  // 检查是否支持 WebGPU
  const hasWebGPU = navigator.gpu !== undefined;
  const device = hasWebGPU ? 'webgpu' : 'wasm';
  console.log(`正在初始化推理引擎，模式: ${device}`);

  segmenterInstance = await pipeline('image-segmentation', 'birefnet', {
    device: device,
    progress_callback: onProgress // 可用于展示局域网下载进度条
  });

  return segmenterInstance;
}

// 执行抠图
export async function removeBackground(imageFile) {
  const segmenter = await initModel();
  
  // 生成可供模型读取的 URL
  const imageUrl = URL.createObjectURL(imageFile);
  
  // 执行推理（纯本地计算）
  const result = await segmenter(imageUrl);
  URL.revokeObjectURL(imageUrl);

  // result 内部包含处理后的蒙版或透明图像
  return result; // 返回处理后的 RawImage / Canvas / Blob
}
```

#### 前端交互与上传逻辑组件示例

```javascript
async function handleProcessAndSave(file, userToken) {
  try {
    showLoading("正在利用本地硬件抠图中...");
    
    // 1. 浏览器本地计算
    const cutoutResult = await removeBackground(file);
    const cutoutBlob = await cutoutResult.toBlob(); // 转为 PNG Blob
    
    // 2. 页面即时预览给用户看
    const previewUrl = URL.createObjectURL(cutoutBlob);
    renderPreview(previewUrl);

    // 3. 异步提交给当前账号服务端归档
    showLoading("正在保存到个人相册...");
    const formData = new FormData();
    formData.append('image', cutoutBlob, `cutout_${Date.now()}.png`);
    formData.append('original_name', file.name);

    const res = await fetch('/api/user/images/save', {
      method: 'POST',
      headers: {
        'Authorization': `Bearer ${userToken}` // 携带当前账号 Token
      },
      body: formData
    });

    const data = await res.json();
    showToast("保存成功！");
  } catch (err) {
    console.error("处理失败", err);
    showToast("处理失败: " + err.message);
  }
}
```

### 四、 后端多账号隔离设计（以 FastAPI/Node.js 为例）

后端无需任何 AI 计算库（无需 PyTorch、无需 onnxruntime），仅做普通的文件 I/O 和数据库记录。

#### 1. 目录隔离规范
```text
/data/system_uploads/
├── user_1001/
│   ├── original/
│   └── cutouts/
│       └── 20260903_abc123.png
├── user_1002/
│   └── cutouts/
└── ...
```

#### 2. 数据库设计 (`user_images` 表)
| 字段         | 类型        | 说明                              |
| :----------- | :---------- | :-------------------------------- |
| `id`         | BIGINT (PK) | 主键                              |
| `user_id`    | BIGINT      | 账号 ID（外键索引，做多租户隔离） |
| `filename`   | VARCHAR     | 存储文件名                        |
| `file_path`  | VARCHAR     | 物理存储路径                      |
| `file_size`  | INT         | 文件大小                          |
| `created_at` | TIMESTAMP   | 处理时间                          |

#### 3. 后端接口实现 (FastAPI 示例)

```python
from fastapi import FastAPI, Depends, UploadFile, File, Form, HTTPException, status
from fastapi.security import OAuth2PasswordBearer
import shutil
import os
from datetime import datetime

app = FastAPI()

UPLOAD_BASE = "/data/system_uploads"

# 鉴权依赖项：获取当前登录用户
async def get_current_user(token: str = Depends(OAuth2PasswordBearer(tokenUrl="token"))):
    user = verify_jwt_token(token) # 业务原有的鉴权函数
    if not user:
        raise HTTPException(status_code=401, detail="无效凭证")
    return user

@app.post("/api/user/images/save")
async def save_cutout_image(
    image: UploadFile = File(...),
    original_name: str = Form(...),
    current_user: dict = Depends(get_current_user)
):
    user_id = str(current_user["id"])
    
    # 账号目录隔离
    user_dir = os.path.join(UPLOAD_BASE, f"user_{user_id}", "cutouts")
    os.makedirs(user_dir, exist_ok=True)
    
    # 防止重名
    timestamp = datetime.now().strftime("%Y%m%d%H%M%S")
    safe_filename = f"{timestamp}_{image.filename}"
    file_path = os.path.join(user_dir, safe_filename)
    
    # 落盘
    with open(file_path, "wb") as buffer:
        shutil.copyfileobj(image.file, buffer)
        
    # 保存入库并绑定账号
    record_id = db.insert_image_record(
        user_id=user_id,
        original_name=original_name,
        storage_path=file_path,
        size=os.path.getsize(file_path)
    )
    
    return {"code": 0, "msg": "ok", "data": {"imageId": record_id, "url": f"/files/user_{user_id}/{safe_filename}"}}
```

### 五、 核心收益与避坑指南

1. **零服务器硬件压力**：
   无论局域网内是 5 个人还是 50 个人同时点击抠图，Ubuntu 服务器只接收少量的静态文件请求和常规 HTTP 上传，**CPU 占用率通常低于 5%**。
2. **离线高可用**：
   全套模型、Nginx、前端与后端都在局域网内，外网哪怕断网，整个系统依然 100% 正常运转。
3. **老旧电脑降级方案**：
   如果局域网内有部分老旧办公机不支持 WebGPU，`@huggingface/transformers` 会自动降级为 **WASM (CPU)** 运行。老电脑会稍慢几秒（约 8~12 秒），但依然能在客户端跑完，绝不会回退到服务器去争抢服务器 CPU。
