# 节点输入输出声明式接线（inputSlots）

> 本文档总结画板节点系统「输入/输出」的声明式接线机制：输入槽位声明以**后端为唯一权威**，
> 经 `node-registry` 下发前端，执行引擎数据驱动收集上游。配套代码：
> 后端 `backend/app/modules/bookplate/node_types.py`（声明）、
> 前端 `frontend/src/modules/bookplate/nodeTypes.ts`（收集器）、
> `frontend/src/app/routes/BookplatePage.tsx`（执行引擎）。

---

## 1. 背景：为什么声明式、为什么下沉后端

节点之间的输入输出接线（「哪个上游节点类型 → 提供什么输入」）**曾经是硬编码**在
`BookplatePage.tsx` 的 `runNode` switch 分支里（如 `findUpstream(node.id, 'book_info')`）。

现在为「模板声明 + 通用收集器」：

- **后端 `node_types.py`** 在模板定义里声明 `input_slots`（唯一权威）：
  `{"slot": "metadata", "from": ["book_info"]}` 等；
- **`node-registry` API** 把模板（含 `input_slots`）原样下发前端；
- **前端 `buildInputSlotsMap()`** 把下发声明转换为「节点类型 → 槽位数组」查找映射；
- **执行引擎**（`runNode`、auto-run 就绪检查）通过 `resolveNodeInputs()` 读取该映射收集上游；
- 节点对外输出由统一的 `nodeOutputText()` 按类型提取（仍在前端）。

效果：

| 场景 | 做法 |
|---|---|
| 新增一个节点类型 | 后端声明模板 + `input_slots`，前端写组件/端点，**不用改其他节点的分发代码** |
| 让新节点喂给已有节点 | 在后端已有节点声明的 `from` 数组里加一行类型，前端自动生效 |
| 让已有节点喂给新节点 | 在新节点后端声明里加一个槽位 |
| 节点需要「任意直接父节点」的内容 | 用通用的直接父节点输出机制（如 AI 对话节点，前端逻辑） |

## 2. 机制总览

### 2.1 后端声明（唯一权威）

`backend/app/modules/bookplate/node_types.py` 的可配置模板 dict 内：

```python
{
    "type": NODE_PROMPT,
    ...
    "input_slots": [
        {"slot": "metadata", "from": [NODE_BOOK_INFO]},
        {"slot": "analysis", "from": [NODE_IMAGE_ANALYSIS]},
        {"slot": "text", "from": [NODE_TEXT, NODE_CHAT]},   # ← 想让新节点喂进来，只改这一行
    ],
}
```

槽位语义约定（`slot`）：

| 槽位 | 含义 | 消费方提取方式 |
|---|---|---|
| `metadata` | 图书元数据 | `book_info.data`（过滤图片字段） |
| `text` | 文本内容 | `text.content` / `chat.output` |
| `analysis` | 图片分析文本 | `image_analysis.analysis` |
| `prompt` | 提示词文本 | `prompt_generation.content` |
| `image` | 图片数据 URL | `image_upload.imageUrl` |

### 2.2 前端类型（`platform/types/index.ts`）

```ts
export type InputSlotName = 'metadata' | 'text' | 'analysis' | 'prompt' | 'image';
export interface InputSlot { slot: InputSlotName; from: CanvasNodeType[]; }
// NodeTemplate 增加：input_slots?: InputSlot[];   // 与后端下发字段（snake_case）一致
```

### 2.3 前端收集器（`nodeTypes.ts`）

```ts
buildInputSlotsMap(templates: NodeTemplate[]): InputSlotsMap
// 后端模板数组（snake_case input_slots）→ Record<CanvasNodeType, InputSlot[]>

resolveNodeInputs(node, nodes, edges, inputSlots: InputSlotsMap): ResolvedNodeInputs
// 按 node.type 查映射，对每个槽位沿入边向上 BFS，取最近的、类型属于 from 的祖先节点
// 返回 Partial<Record<InputSlotName, GraphNode>>，不提取内容，由消费方按类型提取
```

### 2.4 统一输出提取（前端 `nodeTypes.ts`）

```ts
nodeOutputText(node): string   // 任意节点的对外文本输出（供下游作为输入）
bookMetadataText(data): string // 图书元数据 → 文本（过滤 cover_image 等图片字段，保留 isbn）
```

`nodeOutputText` 按类型映射：

| 节点类型 | 输出字段 |
|---|---|
| `book_info` | `bookMetadataText(data)`（过滤图片字段） |
| `text` | `data.content` |
| `prompt_generation` | `data.content` |
| `image_analysis` | `data.analysis` |
| `chat` | `data.output`（**最后一轮助手回复**） |
| `image_generation` | `data.prompt` |
| `image_upload` | `''`（无文本输出） |

### 2.5 通用「直接父节点」机制（前端逻辑）

`inputSlots` 的 BFS 适合「找**特定类型**的祖先」；当节点需要「**任意**直接父节点的输出」
（如 AI 对话节点的「紧随的上一级节点内容」）时用通用机制：

```ts
const parents = nodes.filter((n) => edges.some((e) => e.target === node.id && e.source === n.id));
const texts = parents.map((p) => nodeOutputText(p)).filter((t) => t.trim());
```

这天然支持链式串联（如 ChatBot → ChatBot）。

## 3. 当前各节点声明清单（现状）

> 以下为 `backend/app/modules/bookplate/node_types.py` 的**真实声明**（唯一权威），
> 经 `node-registry` 下发前端。

| 节点模板 | 类型 | 可配置 | input_slots（输入声明） | 输出（nodeOutputText） |
|---|---|---|---|---|
| 图书元数据 | `book_info` | ❌ | 无（根输入节点） | 元数据文本（过滤图片） |
| 图片分析 | `image_analysis` | ✅ | `metadata ← [book_info]`、`image ← [image_upload]` | `analysis` |
| 提示词生成 | `prompt_generation` | ✅ | `metadata ← [book_info]`、`analysis ← [image_analysis]`、`text ← [text, chat]` | `content` |
| 图像生成 | `image_generation` | ✅ | `prompt ← [prompt_generation]`、`image ← [image_upload]` | `prompt` |
| 文本 | `text` | ❌ | 无（手动输入节点） | `content` |
| 图片上传 | `image_upload` | ❌ | 无（手动上传节点） | `''` |
| AI 对话 | `chat` | ✅ | `metadata ← [book_info]` + **直接父节点通用机制** | `output`（末轮回复） |

### 各节点实际行为备注（执行代码保留的特殊逻辑）

- **`image_analysis`**：图片来源优先级 = 节点内直接上传的参考图 > 上游 `image_upload` 节点 > 图书封面（`coverUrl` 兜底）；显式连接 `image_upload` 但未上传时保持待运行态、不回退封面。
- **`prompt_generation`**：`text` 槽接受 `text` 与 `chat` 两种来源；无上游输入时进入待运行态。
- **`image_generation`**：`prompt` 就绪（且不在生成中）才运行；连接 `image_upload` 未上传时保持待运行态。
- **`chat`**：不自动执行（需用户输入）；上下文注入见第 5 节。

### 前端执行引擎的异步时序

`node-registry` 为异步加载，而 `runNode` 需要输入声明。处理方式：

- 注册表未加载时，可配置节点无法从「+」菜单创建（其变体来自 `registry.configs`），
  故不存在「声明缺失却执行」的路径；
- 画布恢复（localStorage）的节点可能在注册表加载前触发 auto-run 检查 → 此时视为输入未就绪
  （保持待运行态），**auto-run 效果依赖 `inputSlotsMap`**，注册表到达后自动补跑。

## 4. 新增节点操作指南

### A. 全新节点类型（完整清单）

1. **后端模板 + 输入声明**：`backend/app/modules/bookplate/node_types.py`
   - 定义 `NODE_XXX` 常量，在 `NODE_TEMPLATES` 加入模板；
   - **按需在模板 dict 中声明 `input_slots`**（见 B/C）；基础输入节点不声明；
2. **前端类型**：`frontend/src/platform/types/index.ts`
   - `CanvasNodeType` 加入 `'xxx'`；如有新数据结构一并声明；
3. **前端模板展示**：`frontend/src/modules/bookplate/nodeTypes.ts`
   - `NODE_DEFAULT_SIZES` 加默认尺寸；`NODE_TEMPLATES` 加入模板（**不再声明 inputSlots**）；
   - 若该节点有文本输出，在 `nodeOutputText()` 加一个 case；
4. **布局尺寸**：`frontend/src/modules/bookplate/nodeLayout.ts` 的 `NodeType` 与 `NODE_SIZES` 同步；
5. **节点组件**：新建 `frontend/src/modules/bookplate/components/XxxNode.tsx`
   （复用 `CanvasNode`、`Streamdown`、`AgentActivity`、`postSSEStream`、`Toggle` 等公共组件）；
6. **画板接入**：`frontend/src/app/routes/BookplatePage.tsx`
   - `seedDataFor()` 加初始数据；`runNode()` 加 `case`（读 `resolveNodeInputs`）；
   - auto-run 就绪检查加分支；渲染映射加分支；稳定回调按需新增；
7. **后端执行端点**：`backend/app/modules/bookplate/router.py` 新增 `POST /xxx`（SSE 流式，
   按节点配置分发 LLM / Agent 模式），用 `_resolve_node_config(db, config_id, NODE_XXX)` 校验；
8. **管理端标签**：`frontend/src/admin/pages/NodeConfigsPage.tsx` 的 `NODE_TYPE_LABEL` 加中文标签。

### B. 让新节点喂给已有节点（后端一行声明）

在**后端已有节点**模板的 `input_slots` 中，把新类型加入对应槽位的 `from` 数组即可，
前端消费方代码（`runNode` case）无需改动。

示例：新增 `chat` 后让「提示词生成」消费它：

```python
# backend node_types.py 中 prompt_generation 模板
{"slot": "text", "from": [NODE_TEXT, NODE_CHAT]},   # ← 加入 NODE_CHAT
```

前提：新节点的输出已在 `nodeOutputText()` 中有 case。

### C. 让已有节点喂给新节点（新节点声明槽位）

在**后端新节点**模板里声明 `input_slots`：

```python
"input_slots": [
    {"slot": "metadata", "from": [NODE_BOOK_INFO]},
    {"slot": "text", "from": [NODE_TEXT, NODE_CHAT]},
],
```

### D. 特殊：需要「任意直接父节点」内容（如 AI 对话节点）

`input_slots` 不适用时，在 `runNode` / 上下文构建处直接使用前端通用机制
（`edges` 过滤直接父节点 + `nodeOutputText`），无需后端声明。

### E. 后端 ↔ 前端同步

- **后端 `node_types.py`**：模板 + `input_slots`（唯一权威，展示层 + 执行契约）；
- **前端 `nodeTypes.ts`**：`NODE_TEMPLATES` 仅保留展示元数据（名称/类别/尺寸），**不含 inputSlots**；
- 两端模板列表仍需同步（新增节点两边都加），但**接线契约只改后端一处**。

---

## 5. AI 对话节点（chat）的特殊约定

- **上下文加载设置**（节点内设置弹层，`data.settings`）：`includeBook`（加载根节点图书元数据）、
  `includeUpstream`（加载直接父节点输出），默认均开启；
- **注入时机**：仅「新对话」首轮注入（`messages.length === 0` 时实时读取当前上游数据组装）；
- **输出**：`data.output` = 最后一轮助手回复，供「提示词生成」text 槽与 ChatBot 链式串联消费；
- **会话纪元（epoch）**：清空对话时递增，随请求传给后端，后端据此派生 FastClaw 会话 key
  （`bookplate-{user}-{node_id}-{epoch}`），确保 Agent 模式清空后服务端会话一并重置。

---

## 6. 展望（可选演进方向）

1. **多来源合并**：槽位支持 `multiple`（当前取最近一个匹配祖先），
   支持「多个上游节点合并喂入同一槽位」；
2. **输出类型扩展**：`nodeOutputText` 目前仅文本；后续可扩展结构化输出
   （如图片 URL、JSON），由后端声明输出类型；
3. **服务端执行**：`input_slots` 已下沉后端，为批量执行 / 历史回放 / 定时任务
   等后端驱动执行场景准备好了契约基础。
