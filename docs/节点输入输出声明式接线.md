# 节点输入接线（连线即输入 · 端口类型匹配）

> 本文档描述画板节点「输入/输出」的接线机制（**破坏性更新，不再向后兼容**）：
>
> - **连线即输入**：节点的输入 = 直接连线的上级节点（1 级），不再沿祖先链向上追溯（BFS 已移除）；
> - **端口类型**：每个节点模板声明「输出类型 + 接受的输入类型列表」，连线类型不匹配时给出软提示（红线 + 徽标 + 运行提示）；
> - **图书元数据**：通过节点「运行设置」中的「包含图书元数据」开关（上下文配置）注入，与是否连线无关；
> - **手动运行**：节点默认不自动运行，点击「运行」按钮执行；可逐节点开启「自动运行」。

配套代码：
- 后端 `backend/app/modules/bookplate/node_types.py`（端口类型声明，唯一权威）
- 前端 `frontend/src/modules/bookplate/nodeTypes.ts`（端口静态镜像 + 匹配）、`execution.ts`（输入收集纯函数）、`useNodeExecution.ts`（执行引擎）、`BookplatePage.tsx`（画布组合）

---

## 1. 核心机制

### 1.1 连线即输入（直接上级，1 级）

`resolveDirectParents(nodeId, nodes, edges)` 只取**直接**连线的上级节点（画线连上即输入），
不再像旧版 `findUpstreamAny` 那样沿整条祖先链向上 BFS 追溯。输入收集见 `execution.ts` 的
`resolveNodeRunInputs()`：按节点类型各取所需，多个同类上级自动合并：

| 节点 | 使用哪些直接上级 | 合并方式 |
|---|---|---|
| 图片分析 | `image_upload`（参考图）、`book_info`/根节点元数据（封面兜底） | 图片取第一个；封面走 `coverUrl` |
| 提示词生成 | `image_analysis`（分析）、`text` / `chat`（文本上下文）、元数据 | 分析/文本分别合并 |
| 图像生成 | `prompt_generation`（提示词）、`text` / `chat`（并入提示词上下文）、`image_upload`（图生图参考） | 提示词优先，无则回退元数据文本；文本并入 |
| AI 对话 | 任意直接上级的文本输出（`includeUpstream`） | 逐节点收集 |

### 1.2 手动拖线连线（自由搭建）

除「＋」按钮自动连线外，可在画布上**手动拖线**连接任意两个节点：

- 按住源节点**右侧连接点（输出端口）**拖拽 → 出现跟随鼠标的幽灵连线（`ConnectionGhost`）；
- 松手落在目标节点**左侧连接点（输入端口）**或**节点卡片任意位置**上即创建连线（`useManualConnection`）；
- 拖拽中**实时类型匹配着色**：幽灵线命中可匹配目标 → 主色加粗；命中类型不匹配目标 → 红色；
  未悬停到目标 → 弱化中性色（匹配/不匹配一眼可辨，无需等到松手）;
- 全程软校验：**禁止自连 / 重复连线（同 source→target）/ 成环**（会 toast 提示并忽略）；
  端口类型不匹配**不禁止**，连线照建、渲染时标红（与 1.3 软提示一致）；
- 创建前记历史（Ctrl+Z 可撤销）；`Esc` 或空白处松手取消。

实现链路：`CanvasNode` 右锚点 `onPointerDown` → `CanvasContext.onAnchorPointerDown` →
`useManualConnection.onAnchorPointerDown`（登记源节点 + window 监听）→ 指针移动 `elementFromPoint`
检测落点（`[data-anchor-input]` 锚点优先，`[data-node-id]` 整卡兜底）并按 `matchPortType` 实时着色
（幽灵线命令式更新，零 React 渲染）→ 松手校验后 `setEdges`。

### 1.3 端口类型（后端声明，唯一权威）

`backend/app/modules/bookplate/node_types.py` 每个模板声明：

```python
{
    "type": NODE_IMAGE,
    ...
    "output_type": "image",        # 该节点产出什么
    "input_types": ["text", "image"],  # 接受哪些类型的上级输入（空 = 不接受上游）
}
```

端口类型枚举：`text / image / document / audio / video / any`（`any` = 任意，如 AI 对话的任意上级内容）。
当前实际使用 `text` 与 `image`，其余为未来节点预留。

前端 `nodeTypes.ts` 的 `NODE_PORT_TYPES` 为**静态镜像**（注册表异步加载期间 + 管理页展示兜底），
注册表到达后以后端权威值覆盖；`matchPortType(source, targetTypes)` 判定：
- `any` 匹配任意；目标输入列表为空 = 不接受任何上游输入；
- 任一侧类型未知返回 `unknown`（不判为不匹配，避免误报）。

### 1.4 类型不匹配 = 软提示（不禁止连线）

| 位置 | 表现 |
|---|---|
| 连线 | 红色虚线（`NodeEdge.compatible=false`） |
| 目标节点标题旁 | 「类型不匹配 ×N」红色徽标（`CanvasNode.mismatchBadge`） |
| 点击「运行」 | toast 明确原因（如「连线「图片上传」类型不匹配，已标红」） |

连线本身仍可建立（保持搭建自由）；不匹配的输入在运行时被忽略并给出提示。

### 1.5 图书元数据：上下文配置（`NodeRunSettings`）

可执行节点（图片分析 / 提示词生成 / 图像生成）的「运行设置」弹层（节点组件右上角 ⚙）：

- **包含图书元数据**（`includeBook`）：开启时无论是否直接连线，都把画布**根** `book_info`
  节点（无入边者优先）的元数据作为上下文注入；直接连线了 `book_info` 时天然生效。
  默认值 = **直接上级是图书元数据才开启**，否则关闭。
- **自动运行**（`autoRun`）：默认关闭（手动运行）；开启后输入就绪时自动补跑。

### 1.6 手动运行

- 新增节点默认不自动执行（`handlePickChildFor` 仅在节点开启「自动运行」时创建后补跑）；
- 每个可执行节点在待运行态提供「运行」按钮（▶）；
- `runNode(node)` 返回**待运行原因字符串**（输入不足 / 类型不匹配 / 图片上传未就绪等），
  `handleRunFor` 以 toast 提示；执行成功返回空串。
- 自动运行检查（`autoRun` 节点）与 `runNode` 共用 `resolveNodeRunInputs`，口径一致。

## 2. 当前各节点端口声明（真实清单）

> 以 `backend/app/modules/bookplate/node_types.py` 为准（唯一权威）。

| 节点模板 | 类型 | 可配置 | 输出类型 | 接受的输入类型 |
|---|---|---|---|---|
| 图书元数据 | `book_info` | ❌ | `text` | （无，手动输入 ISBN） |
| 文本 | `text` | ❌ | `text` | （无，手动输入） |
| 图片上传 | `image_upload` | ❌ | `image` | （无，手动上传） |
| 图片分析 | `image_analysis` | ✅ | `text` | `image`、`text` |
| 提示词生成 | `prompt_generation` | ✅ | `text` | `text` |
| 图像生成 | `image_generation` | ✅ | `image` | `text`、`image` |
| AI 对话 | `chat` | ✅ | `text` | `text` |

**示例**：`image_upload → prompt_generation` 会标红（图片上传输出 `image`，提示词生成仅接受 `text`）；
`image_upload → image_generation` / `image_upload → image_analysis` 正常。

## 3. 新增节点操作指南

1. **后端模板 + 端口声明**：`backend/app/modules/bookplate/node_types.py`
   - 定义 `NODE_XXX` 常量，加入 `NODE_TEMPLATES`；
   - 声明 `output_type`（产出类型）与 `input_types`（接受的输入类型列表）；
2. **前端类型**：`frontend/src/platform/types/index.ts` 的 `CanvasNodeType` 加入 `'xxx'`；
3. **前端展示**：`nodeTypes.ts` 的 `NODE_TEMPLATES`（展示元数据）、`NODE_DEFAULT_SIZES`、
   `NODE_COLORS`、`NODE_PORT_TYPES`（静态端口镜像）同步；
4. **布局尺寸**：`nodeLayout.ts` 的 `NODE_SIZES` 同步；
5. **节点组件**：新建 `components/XxxNode.tsx`（复用 `CanvasNode`、`NodeSettingsPopover`、`Streamdown` 等）；
6. **画板接入**：`BookplatePage.tsx` 的 `seedDataFor()`（含默认 `settings`）加分支；`execution.ts` 的
   `resolveNodeRunInputs()` 按需补充消费逻辑；`CanvasNodeViews.tsx` 加渲染分支；
7. **后端执行端点**：`backend/app/modules/bookplate/router.py` 新增 `POST /xxx`（SSE 流式）；
8. **管理端**：`NodeConfigsPage.tsx` 的 `NODE_TYPE_LABEL` 加中文标签（端口类型只读展示，无需编辑）。

> 接线契约只改后端一处（`node_types.py` 端口声明），前端执行引擎按直接连线 + 类型自动适配。

## 4. 代码结构（BookplatePage 拆分后）

| 文件 | 职责 |
|---|---|
| `graphTypes.ts` | 节点/连线/历史快照类型与常量 |
| `nodeTypes.ts` | 模板展示、端口类型镜像与匹配、输出文本提取、直接上级/根节点查找 |
| `execution.ts` | 输入收集纯函数（`resolveNodeRunInputs`）、类型不匹配收集、待运行原因 |
| `useNodeExecution.ts` | SSE 执行引擎（各 `run*` 函数 + `runNode` 分发） |
| `useCanvasHistory.ts` | 撤销/重做 |
| `useGenerationHistory.ts` | 历史记录（stage_results）组装与保存 |
| `CanvasNodeViews.tsx` | 画布节点渲染树（按类型分发到组件） |
| `useManualConnection.ts` | 手动拖线连线状态机（防重/防环、可撤销、幽灵连线） |
| `ConnectionGhost.tsx` | 跟随指针的幽灵连线（fixed 覆盖层，命令式更新） |
| `BookplatePage.tsx` | 画布组合：状态、回调、自动运行检查、渲染 |

## 5. 历史演进

- **旧版 input_slots**：后端声明「槽位 ← 可接受的上游类型」，执行引擎沿祖先链 BFS 取最近匹配，
  面板无法从连线直观得知输入来源 → 已移除；
- **现版**：连线即输入（1 级）+ 手动拖线连线 + 端口类型软校验 + 图书元数据上下文配置 + 手动运行。
