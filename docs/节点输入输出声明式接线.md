# 节点输入接线（连线即输入 · 端口类型匹配 · 占位符模板）

> 本文档描述画板节点「输入/输出」的接线机制（**破坏性更新，不再向后兼容**）：
>
> - **连线即输入**：节点的输入 = 直接连线的上级节点（1 级），不再沿祖先链向上追溯（BFS 已移除）；
> - **端口类型**：每个节点模板声明「输出类型 + 接受的输入类型列表」，连线类型不匹配时给出软提示（红线 + 徽标 + 运行提示）；
> - **图书元数据**：通过节点「运行设置」中的「包含图书元数据」开关（上下文配置）注入，与是否连线无关；
> - **手动运行**：节点默认不自动运行，点击「运行」按钮执行；可逐节点开启「自动运行」；
> - **占位符模板（文本聚合）**：文本输出节点可被 `{占位符}` 引用，按自定义格式拼接多上级文本；
>   **能力由端口类型声明 + 文本字段约定推导，新增文本输出节点类型默认支持，无需改占位符代码**（见 1.7）。

配套代码：
- 后端 `backend/app/modules/bookplate/node_types.py`（端口类型声明，唯一权威）
- 前端 `frontend/src/modules/bookplate/nodeTypes.ts`（端口静态镜像 + 匹配 + 输出文本提取）、`execution.ts`（输入收集纯函数）、`textTemplate.ts`（占位符引擎）、`components/PlaceholderPanel.tsx`（占位符来源公共组件）、`useNodeExecution.ts`（执行引擎）、`useChatExecution.ts`（AI 对话执行）、`BookplatePage.tsx`（画布组合）

## 1. 核心机制

### 1.1 连线即输入（直接上级，1 级）

`resolveDirectParents(nodeId, nodes, edges)` 只取**直接**连线的上级节点（画线连上即输入），
不再像旧版 `findUpstreamAny` 那样沿整条祖先链向上 BFS 追溯。输入收集见 `execution.ts` 的
`resolveNodeRunInputs()`：按节点类型各取所需，多个同类上级自动合并：

| 节点 | 使用哪些直接上级 | 合并方式 |
|---|---|---|
| 图片分析 | `image_upload`（参考图）、`book_info`/根节点元数据（封面兜底） | 图片取第一个；封面走 `coverUrl` |
| 提示词生成 | `image_analysis`（分析）、文本输出上级（文本上下文）、元数据 | 分析/文本分别合并 |
| 图像生成 | `prompt_generation`（提示词）、文本输出上级（并入提示词上下文）、`image_upload`（图生图参考） | 提示词优先，无则回退元数据文本；文本并入 |
| AI 对话 | 任意直接上级的文本输出（`includeUpstream`）+ 图片输出（`includeUpstreamImages`，图片上传 / 图像生成） | 文本逐节点收集；图片转 data URL 后作为视觉上下文 |
| 文本聚合 | 全部**文本输出**直接上级（按端口类型声明推导） | 模板中 `{别名}` 逐个替换为对应上级文本；结果随上级变化自动重算 |

> 「文本上下文」收集按端口类型推导（`output ∈ text/any`），因此**任何文本输出节点**（文本 / AI 对话 /
> 文本聚合 / 未来新增）直接连给提示词生成、图像生成都会自动并入上下文，无需逐个枚举节点类型。

### 1.2 手动拖线连线（自由搭建）

除「＋」按钮自动连线外，可在画布上**手动拖线**连接任意两个节点：

- 按住源节点**右侧连接点（输出端口）**拖拽 → 出现跟随鼠标的幽灵连线（`ConnectionGhost`）；
- 松手落在目标节点**左侧连接点（输入端口）**或**节点卡片任意位置**上即创建连线（`useManualConnection`）；
- 拖拽中**实时类型匹配着色**：幽灵线命中可匹配目标 → 主色加粗；命中类型不匹配目标 → 红色；
  未悬停到目标 → 弱化中性色（匹配/不匹配一眼可辨，无需等到松手）;
- 全程软校验：**禁止自连 / 重复连线（同 source→target）/ 成环**（会 toast 提示并忽略）；
  端口类型不匹配**不禁止**，连线照建、渲染时标红（与 1.3 软提示一致）；
- 创建前记历史（Ctrl+Z 可撤销）；`Esc` 或空白处松手取消。

实现链路：`CanvasNode` 右锚点 `onPointerDown` → `CanvasContext.onAnchorPointerDown` →
`useManualConnection.onAnchorPointerDown`（登记源节点 + window 监听）→ 指针移动 `elementFromPoint`
检测落点（`[data-anchor-input]` 锚点优先，`[data-node-id]` 整卡兜底）并按 `matchPortType` 实时着色
（幽灵线命令式更新，零 React 渲染）→ 松手校验后 `setEdges`。

### 1.3 端口类型（后端声明，唯一权威）

`backend/app/modules/bookplate/node_types.py` 每个模板声明：

```python
{
    "type": NODE_IMAGE,
    ...
    "output_type": "image",        # 该节点产出什么
    "input_types": ["text", "image"],  # 接受哪些类型的上级输入（空 = 不接受上游）
}
```

端口类型枚举：`text / image / document / audio / video / any`（`any` = 任意类型，预留）。
当前实际使用 `text` 与 `image`，其余为未来节点预留。

前端 `nodeTypes.ts` 的 `NODE_PORT_TYPES` 为**静态镜像**（注册表异步加载期间 + 管理页展示兜底），
注册表到达后以后端权威值覆盖；`matchPortType(source, targetTypes)` 判定：
- `any` 匹配任意；目标输入列表为空 = 不接受任何上游输入；
- 任一侧类型未知返回 `unknown`（不判为不匹配，避免误报）。

### 1.4 类型不匹配 = 软提示（不禁止连线）

| 位置 | 表现 |
|---|---|
| 连线 | 红色虚线（`NodeEdge.compatible=false`） |
| 目标节点标题旁 | 「类型不匹配 ×N」红色徽标（`CanvasNode.mismatchBadge`） |
| 点击「运行」 | toast 明确原因（如「连线「图片上传」类型不匹配，已标红」） |

连线本身仍可建立（保持搭建自由）；不匹配的输入在运行时被忽略并给出提示。

### 1.5 图书元数据：上下文配置（`NodeRunSettings`）

可执行节点（图片分析 / 提示词生成 / 图像生成）的「运行设置」弹层（节点组件右上角 ⚙）：

- **包含图书元数据**（`includeBook`）：开启时无论是否直接连线，都把画布**根** `book_info`
  节点（无入边者优先）的元数据作为上下文注入；直接连线了 `book_info` 时天然生效。
  默认值 = **直接上级是图书元数据才开启**，否则关闭。
- **自动运行**（`autoRun`）：默认关闭（手动运行）；开启后输入就绪时自动补跑。

### 1.6 手动运行

- 新增节点默认不自动执行（`handlePickChildFor` 仅在节点开启「自动运行」时创建后补跑）；
- 每个可执行节点在待运行态提供「运行」按钮（▶）；
- `runNode(node)` 返回**待运行原因字符串**（输入不足 / 类型不匹配 / 图片上传未就绪等），
  `handleRunFor` 以 toast 提示；执行成功返回空串。
- 自动运行检查（`autoRun` 节点）与 `runNode` 共用 `resolveNodeRunInputs`，口径一致。

### 1.7 占位符模板（文本聚合 · 公共机制）

「文本聚合」节点用 **模板 + 占位符** 把多个上级文本按自定义格式拼接：

```
## 我是自定义标题

{我是上级节点1的占位符}

---

## 我是另一个自定义标题

{我是上级节点2的占位符}
```

**两处关键推导（新增文本节点零成本接入）：**

1. **谁可以被引用**：占位符能力 = 端口类型声明推导。`isTextOutputNode(node, portTypesOf)`
   判定 `output ∈ {text, any}` 即认为该节点产出可引用文本（`image` 输出的图像生成 / 图片上传不参与）。
   因此新增节点只要声明 `output_type: "text"`，无需改占位符代码即可被引用。
2. **文本从哪提取**：`nodeTypes.ts` 的 `nodeOutputText()` 有**约定式兜底**——按
   `data.output → data.content → data.analysis` 顺序读取。新增文本节点把对外文本存入任一约定字段
   即自动可读（无需逐个加 case）。

**实现分层（高内聚低耦合，可复用）：**

| 层 | 文件 | 职责 |
|---|---|---|
| 引擎 | `textTemplate.ts` | 占位符解析 / 别名同步 / 渲染；`toPlaceholderSources()` 把上级节点映射为来源行 |
| 公共组件 | `components/PlaceholderPanel.tsx` | 来源行（色点 + 标题 + 可编辑别名 + 插入按钮）+ 未匹配警告，纯展示受控 |
| 节点 | `components/TextAggregateNode.tsx` | 模板编辑 / 预览 / 光标插入，编排前两层 |

**运行语义**：纯文本变换、不调 API、无「运行」按钮——输出随上级内容 / 连线变化**自动重算**
（`BookplatePage` 的聚合 effect），下游（提示词生成 / 图像生成 / AI 对话 / 其他聚合）直接消费 `data.output`。

> 别名默认取上级节点标题（变体名 / 模板名），同名自动加「· 2」；可在面板内改名，重名会被拒绝。

## 2. 当前各节点端口声明（真实清单）

> 以 `backend/app/modules/bookplate/node_types.py` 为准（唯一权威）。

| 节点模板 | 类型 | 可配置 | 输出类型 | 接受的输入类型 |
|---|---|---|---|---|
| 图书元数据 | `book_info` | ❌ | `text` | （无，手动输入 ISBN） |
| 文本 | `text` | ❌ | `text` | （无，手动输入） |
| 图片上传 | `image_upload` | ❌ | `image` | （无，手动上传） |
| 图片分析 | `image_analysis` | ✅ | `text` | `image`、`text` |
| 提示词生成 | `prompt_generation` | ✅ | `text` | `text` |
| 图像生成 | `image_generation` | ✅ | `image` | `text`、`image` |
| AI 对话 | `chat` | ✅ | `text` | `text`、`image` |
| 文本聚合 | `text_aggregate` | ❌ | `text` | `text` |

**示例**：`image_upload → prompt_generation` 会标红（图片上传输出 `image`，提示词生成仅接受 `text`）；
`image_upload → image_generation` / `image_upload → image_analysis` 正常。

## 3. 新增节点操作指南

> 以「文本判断节点 `text_judge`（输出 `text`）」为例，展示在**既有模块内新增节点类型**的完整步骤。
> 新增独立模块（第二、第三个画板）见 `docs/module-extension-guide.md`。

### 3.1 必改清单

1. **后端模板 + 端口声明**：`backend/app/modules/bookplate/node_types.py`
   - 定义 `NODE_TEXT_JUDGE = "text_judge"` 常量，加入 `NODE_TEMPLATES`；
   - 声明 `output_type`（产出类型）与 `input_types`（接受的输入类型列表）；
   - **文本输出节点**声明 `output_type: "text"` 后，占位符引用与「文本上下文」收集**自动生效**（见 1.7）；
2. **前端类型**：`frontend/src/platform/types/index.ts` 的 `CanvasNodeType` 加入 `'text_judge'`；
3. **前端展示**：`nodeTypes.ts` 的 `NODE_TEMPLATES`（展示元数据）、`NODE_DEFAULT_SIZES`、
   `NODE_COLORS`、`NODE_PORT_TYPES`（静态端口镜像）同步；
4. **布局尺寸**：`nodeLayout.ts` 的 `NodeType` 联合类型与 `NODE_SIZES` 同步；
5. **节点组件**：新建 `components/TextJudgeNode.tsx`；
6. **画板接入**：
   - `BookplatePage.tsx` 的 `seedDataFor()` 加分支（含默认 `data`，可执行节点含 `settings`）；
   - `CanvasNodeViews.tsx` 加渲染分支；有新增交互时在 `NodeViewHelpers` 加稳定回调并在页面实现；
   - `execution.ts`：`resolveNodeRunInputs(node, nodes, edges, portTypesOf)` 按需补充消费逻辑；
     **文本输出节点无需改动**——已被自动并入「文本上下文」（见 1.1 说明）；
   - `useNodeExecution.ts` 的 `runNode` 分发加分支；
7. **后端执行端点**：`backend/app/modules/bookplate/router.py` 新增 `POST /text-judge`（SSE 流式，
   LLM / Agent 双模式参考既有 `generate-prompt` / `chat`）；
8. **管理端**：`NodeConfigsPage.tsx` 与 `PromptsPage.tsx` 的 `NODE_TYPE_LABEL` 加中文标签
   （可配置节点才需要；端口类型只读展示，无需编辑）。

> 接线契约只改后端一处（`node_types.py` 端口声明），前端执行引擎按直接连线 + 类型自动适配。

### 3.2 可复用的公共组件 / 工具

| 组件 / 工具 | 位置 | 用途 |
|---|---|---|
| `CanvasNode` | `platform/components/node/CanvasNode.tsx` | 节点卡片外壳（拖拽 / 缩放 / 锚点 / 徽标 / 右键） |
| `NodeActionBar` | `platform/components/node/NodeActionBar.tsx` | 卡片角上操作按钮组（编辑 / 保存 / 取消 / 重试等） |

| `PlaceholderPanel` | `modules/bookplate/components/PlaceholderPanel.tsx` | 占位符来源公共组件（别名编辑 / 插入 / 未匹配提示） |
| `textTemplate.ts` 引擎 | `modules/bookplate/textTemplate.ts` | `toPlaceholderSources()` 映射来源；`renderAggregateTemplate()` 渲染；`isTextOutputNode()` 判定 |
| 基础 UI | `platform/components/ui/` | `Input` / `Textarea` / `Select` / `Toggle` / `Button` / `Tooltip` 等，样式统一走 `index.css` 的 paper/ink/accent 主题变量 |

### 3.3 注意事项

- **占位符零成本接入**：文本输出节点只需声明 `output_type: "text"` + 把对外文本存入
  `data.output / content / analysis` 任一字段，即自动获得「被占位符引用 + 并入文本上下文」两种能力；
- **端口查找**：`PortTypesLookup` 定义在 `nodeTypes.ts`（`execution.ts` 再导出保持 import 路径），
  由画布 `portTypesOf` 提供（后端模板声明优先，前端静态镜像兜底）；
- **纯变换节点**（如文本聚合，不调 API）：不提供「运行」按钮，输出由 `BookplatePage` 的聚合 effect
  随上级变化自动重算并写入 `data.output`，无需走 `runNode`；
- **历史记录**：`useGenerationHistory.ts` 按直接上级组装 stage 结果——若提示词路径经聚合节点中转，
  stage2.prompt 可能为空（边界场景，按需扩展）；
- **`nodeOutputText` 约定**：不要破坏 `output → content → analysis` 的兜底顺序；已有类型的精确 case 优先。
  兜底只读**字符串**字段——若某节点把结构化对象存在 `data.output`，文本提取会得到空串，请使用精确 case；
- **特殊语义分桶**：新文本节点默认并入「文本上下文」，够用即可；若需要**独立语义槽位**（如图片分析的
  `analysis`、提示词生成的 `prompt` 单独收集），需在 `resolveNodeRunInputs` 的文本上下文过滤中把该类型
  加入排除清单（`type !== ...`）并补一段专门收集——否则其文本会被静默归入通用上下文。

## 5. 历史演进

- **旧版 input_slots**：后端声明「槽位 ← 可接受的上游类型」，执行引擎沿祖先链 BFS 取最近匹配，
  面板无法从连线直观得知输入来源 → 已移除；
- **现版**：连线即输入（1 级）+ 手动拖线连线 + 端口类型软校验 + 图书元数据上下文配置 + 手动运行；
- **占位符模板（文本聚合）**：多文本上级的自定义格式化拼接；能力由「端口类型声明 + 文本字段约定」
  推导（`isTextOutputNode` + `nodeOutputText` 兜底），新增文本输出节点默认支持；
  文本上下文收集同步改为按端口类型推导（`resolveNodeRunInputs` 需传 `portTypesOf`）。
