## 方案调整（用户确认）+ 已落地实现

- 用户指出 FastClaw skills 是 agent 级共享、只有 session 隔离，画布侧动态注入会互相污染 → **改为 admin 统一管理**：不给画布用户开放。用户选择：配置表加 JSON 列、保存即同步 + 手动重推、编辑弹窗内多选。
- 新增 `fastclaw.data_root`（admin/settings「其他」，默认 `/opt/fastclaw-data`，留空回退 env FASTCLAW_DATA_ROOT → /var/lib/fastclaw）；`fastclawDataRoot(configured?)` 由路由传 DB 值，保持模块不依赖 DB，产物桥接与技能同步共用一个根。
- `fastclaw_agent_configs.skills TEXT NOT NULL DEFAULT '[]'`（schema.ts + database.ts ensureColumn + DDL 幂等补列）；admin API 新增 GET /skills 候选、POST /:id/sync-skills 重推，POST/PATCH 返回 `skill_sync`，非法名单 400，仅启停不触发同步，删除配置不动磁盘。
- 新模块 `backend-ts/src/services/ai/fastclaw-skills.ts`：共享区 `runtime/.agent/skills` + 同捆包候选；目标 `{root}/agents/{agentId}/agent/skills/{name}`；staging + rename 原子替换、`.bf-skills.json` 内容哈希幂等、只清理托管项、跳过 .env*、agentId/skill 名与 realpath 校验。`isValidSkillName` / `REPO_ROOT` 提到 skill-agent-service.ts 共用。
- 前端 FastClawAgentsPage 弹窗加技能多选（搜索/已选 chips），卡片加重新同步按钮与 skills 计数；settings KNOWN_KEYS 补提示。
- 验证：前后端 tsc 通过；新增 fastclaw-skills.test.ts(9) 与 fastclaw-agents-admin.test.ts(4) 全过；platform.test.ts(19) 全过；full suite 357/365，剩余 8 个为预存在 Windows 路径/标注 schema 漂移/并行干扰（tasks/todo.md:69 有记录）。本机 `node -v` 是 22，但 better-sqlite3 用 Node 24 编译，DB 测试须用 `/c/Program Files/nodejs/node.exe` 跑 vitest。
